# 第一轮：下载可靠性修复

日期：2026-10-13

本文件保留第一轮历史记录；下方“尚未完成”是当时的状态。后续进展见[第二轮说明](reliability-second-round.md)。

## 已完成

1. 网页链接不再作为完成状态跳过，二次检索覆盖仅保存网页的条目。
2. 续传核对 DOI/引用文本和可解析的 PDF，不再只按编号或文件名前缀恢复；清单增加文件 SHA-256。
3. 单篇、批量、IEEE 两种 PDF 路径、Springer 与中文期刊使用同一套 PDF 结构检查和安全保存逻辑。
4. 临时文件核验后发布，独占预留目标文件名；同名保存和并发保存不会直接覆盖旧文件。
5. 首轮及二次检索使用统一的域名限定 Cookie jar，DOI-only 条目及跳转后的出版社也可获得相应 Cookie；不把 Cookie 拼成全局请求头。
6. 修复交互式配置保存后把配置字典覆盖为 `None` 的错误。
7. 读取首轮和二次检索 Future 的异常，保存条目级错误及日志，保留其他任务的成果。
8. DOI/URL 断行处理保护实际连字符；普通文字断词处理保持原行为。
9. JSON、Markdown、CSV 输出采用临时文件替换。

没有删除已有论文，没有读取真实 Cookie，也没有修改其内容；保留了此前的源码改动。

## 验证方法

最终项目测试：**284 项通过，耗时 1.22 秒**，其中新增离线回归用例 50 项。语法编译、两个命令行入口的帮助启动、Git 补丁格式检查均通过。

此前工作区下载适配器的 **5 项离线兼容性测试也通过**，耗时 0.26 秒。

- 新增离线回归测试，包含 HTML 伪 PDF、损坏/加密文件、同名/并发保存、异常清理、文件变化、不同论文相同编号、站点适配、Cookie 重定向及域名限制、任务异常、交互配置、DOI 断行和写入失败保护。
- 使用实际 requests Session 和离线适配器验证 DOI → IEEE 重定向：IEEE Cookie 不发送给 DOI 主机，转到 IEEE HTTPS 后才发送。
- 对此前已整理的 50 个真实 PDF 做只读兼容性检查：全部通过结构检查，全部与此前清单中的 SHA-256 相同。
- 运行全套测试、语法编译检查、入口帮助检查和 Git 补丁格式检查，结果以本轮交付说明为准。

测试不请求出版社，也不验证真实机构订阅权限。本轮没有重新联网下载 78 条文献，不能宣称下载成功率或速度已经提高多少。

## 兼容性

- 原有编号命名保留；发生重名时增加后缀。
- 旧清单有 DOI 或完整引用文本、且准确文件路径指向有效 PDF 时仍可恢复；没有哈希不阻止恢复。
- 仅编号、缺失路径、路径越出下载目录、损坏文件或不匹配身份不再视为完成，可能因此重新尝试。这是防止错文献被当成成功的有意变化。
- `file_sha256` 是 JSON 清单新增的可选字段，CSV 原字段不变。
- 不依赖新增第三方库；新核心工具模块沿用项目已有的 pypdf。
